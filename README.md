# Precedent

A searchable index of people who have already completed a specific academic,
career, or life transition — and the exact sequence of steps they took.

It answers one question:

> **Has someone like me already done what I am trying to do, and how did they do it?**

Precedent is a reference tool, closer to a case-law search engine than to
LinkedIn. The unit of value is the sequence of actions, not the person.

## Run it

No database, no search server, no Docker. The API ships an in-process seeded
store so the whole thing runs immediately.

```bash
npm install
npm run build --workspace @precedent/ui-tokens
npm run dev --workspace @precedent/web
```

Then open http://localhost:3000. The index is seeded with 40 pathways across 10
transitions.

To run the standalone API instead:

```bash
npm run dev --workspace @precedent/api
```

Run every test:

```bash
npm test --workspaces --if-present
```

## Layout

```
apps/web/            Next.js 15 App Router, React 19, Tailwind
packages/core/       Domain model — zod schemas, taxonomy, privacy, consent
packages/search/     Query parsing, filter codec, facets, ranking
packages/ui-tokens/  Design tokens → Tailwind preset + CSS vars + RN theme
services/api/        HTTP API, seed generator, Prisma schema
design-system/       Generated design system (MASTER.md) + OVERRIDES.md
TRUST.md             Privacy and safety decisions, as implemented
```

### Rules the structure enforces

**No hardcoded style values.** `packages/ui-tokens` is the only place a hex,
font size, spacing number, radius, or duration is written. It emits a Tailwind
preset for web and a resolved theme object for React Native, so the two
platforms cannot drift.

**Shared logic is shared.** Filter serialization, query parsing, ranking,
pathway validation, and step ordering live in `packages/`. If a bug can happen on
one platform and not the other, the logic is in the wrong place.

**Redaction is a type boundary.** `toPublicPathway()` returns a `PublicPathway`,
a distinct type from `Pathway`. Nothing that consumes public data can be handed
private data, and the search index only accepts the public type — so a private
field cannot reach a facet or a search hit.

## Design system

`design-system/precedent/MASTER.md` is generated by the `ui-ux-pro-max` skill and
is the source of truth. `design-system/OVERRIDES.md` records every place the
build brief's design constraints deliberately override the generator, and why —
undocumented divergence from MASTER is a bug.

The step-type palette was validated with the data-viz palette validator against
Precedent's own surfaces rather than the validator's defaults. Both light and
dark pass the lightness band, chroma floor, CVD separation, and normal-vision
floor. Re-run after any palette change:

```bash
node scripts/validate_palette.js "#2A78D6,#EB6834,#1BAF7A,#EDA100,#E87BA4,#008300,#4A3AA7" --mode light --surface "#FFFFFF"
```

### Two encoding channels, and only two

Saturated colour appears in exactly two places: verification tiers, and
step-type coding on timelines. Everything else is neutral. On a results page
showing 40 pathways, every saturated pixel competes with the two channels that
actually carry meaning.

Fourteen step types are grouped into **seven hue families**, because a
categorical palette may not exceed eight hues and hues are never cycled. Within a
family, the icon and the visible label carry the distinction. `setback` gets no
hue at all — it renders recessed, which keeps setbacks visible without making
them look like errors, and keeps red reserved for destructive actions.

## What the tests actually guard

79 tests, all passing. The ones worth knowing about:

| Guarantee | Where |
|---|---|
| Text contrast ≥ 4.5:1 in **both** themes, computed not eyeballed | `packages/ui-tokens/test/contrast.test.js` |
| A realistic pathway with setbacks round-trips the schema | `packages/core/test/domain.test.js` |
| An anonymous pathway never leaks a real name — swept across all 40 seeded pathways and every response | `services/api/test/api.test.js` |
| Facet counts match an independent count over the corpus | `packages/search/test/search.test.js` |
| Selecting within a facet doesn't collapse its own sibling options | `packages/search/test/search.test.js` |
| Engagement is structurally absent from ranking | `packages/search/test/search.test.js` |
| Delete propagates to index, caches, and every similar-pathway list | `services/api/test/api.test.js` |
| Prisma enums match the domain model | `packages/core/test/schema-parity.test.js` |
| Every pathway child table cascades on delete | `packages/core/test/schema-parity.test.js` |

Three of these caught real bugs during the build: white-on-accent failing
contrast in dark mode, a background tag miscast into the constraints list, and a
natural-language parse that swallowed the destination when a constraint phrase
was stripped.

## Product rules encoded in the model

- **Setbacks are first-class.** `setback` and `pivot` are step types, and
  submission is blocked at zero recorded obstacles unless the author explicitly
  attests there genuinely were none. A pathway with no friction recorded is
  marked incomplete, not clean.
- **The verification tier is derived, never assigned.** It is always a function
  of the signals present, so it cannot drift from the evidence, and an expiring
  signal demotes the pathway automatically.
- **Verification attaches to claims, not people.** A pathway can hold an
  institution-verified education step next to an unverified compensation figure.
- **Compensation cannot be exact.** The type system only permits a band.
- **The natural-language parser is deterministic** and always returns its
  interpretation as editable chips. No model silently rewrites a query — a silent
  rewrite makes an empty result set unexplainable.
- **Ranking order is fixed:** exact transition match → verification tier →
  completeness → similarity to the viewer → recency. Never engagement.

See `TRUST.md` for the privacy and safety decisions.

## Decisions taken during the build

Four questions were flagged as ask-don't-assume, and were answered:

- **Taxonomy** — seeded from freely-licensed public datasets only (IPEDS, CIP,
  O\*NET); no paid vendor data. Free-text entry is always accepted, and unmatched
  input becomes a provisional node routed to the admin merge queue, so a
  submitter is never blocked by a missing institution.
- **Minors** — browsing is open to all ages; submitting requires 16+, and 16–17
  requires verified parental consent. Withdrawing consent unpublishes
  immediately.
- **Employer names** — published as submitted, compensation always banded, with a
  report/takedown route on every profile.
- **Moderation** — sized for a single part-time reviewer: one risk-ranked queue,
  no assignment model, high-detail-but-unverified scored as elevated risk since
  that is the fabrication signature.

## Status

Built and verified: the design system and token pipeline, the domain model, the
API with seeded faceted search, and the web app (search entry, results with
faceted filtering and the adjacent-pathway empty state, the pathway profile with
its timeline and verification panel, the compare view, the submission wizard
through the obstacle gate, and the trust page).

Not yet built: the Expo mobile app, the server-side verification pipeline and
admin console UI (the risk-ranked queue endpoint exists), the contact relay
transport, saved searches and collections, and auth. `services/api` currently
runs on its in-process seeded store; the Prisma schema is written and
parity-tested but not yet wired to a live Postgres.
